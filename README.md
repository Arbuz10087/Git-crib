# Git-crib — шпаргалка по Git

Личные заметки: команды, ошибки, с которыми сталкивалась, и способы их чинить.

## Базовый цикл работы

```bash
git add .            # добавить все изменения в индекс
git commit -m "..."  # сохранить коммит с сообщением
git push origin main # отправить на GitHub
pwd                          # где я нахожусь
ls -la                       # что лежит в папке
cd ~/projects/Название       # перейти в папку проекта
cd ..                        # на уровень выше
cd ~                         # в домашнюю папку
git branch                # список веток, звёздочка = текущая
git switch main           # переключиться на ветку
git branch -M main        # переименовать текущую ветку в main
git merge 1               # влить ветку 1 в текущую
git branch -d 1           # удалить ветку (безопасно)
git branch -D 1           # удалить ветку принудительно
git push origin --delete 1 # удалить ветку на GitHub
git remote -v                        # показать все remote
git remote add backup <URL>          # добавить второй удалённый
git remote remove backup             # убрать remote
git push backup main                 # пуш в конкретный remote
Ошибки и как их чинить
command not found
Использую команду не из той оболочки. В Git Bash — только Unix-команды (pwd, а не Get-Location).

nothing to commit
Нечего коммитить: либо нет файлов, либо нет изменений. Сначала создать файл и сделать git add .

src refspec main does not match any
Пуш ветки, у которой нет коммитов (или ветка называется иначе, например master). Решение: сделать первый коммит и/или git branch -M main.

Конфликт при merge: CONFLICT (rename/delete)
Git не знает, чью версию файла оставить. Смотрим, какая версия уже лежит в рабочей папке, выбираем нужную:

bash
git add путь/к/файлу    # принимаем эту версию
git commit -m "слил ветку X в main"
not fully merged при удалении ветки
Git перестраховывается. Если точно уверен(а), что всё слито в main — удаляем принудительно: git branch -D имя-ветки.

Важные понимания
Переключение веток меняет файлы на диске! Файлы, которых нет в ветке, «исчезают» из папки и проводника, но остаются в истории Git. Вернуть их можно, вернувшись в нужную ветку или сделав merge.
Git ничего не удаляет сам — исчезнувшие файлы обычно просто лежат в другой ветке.
Предупреждения про LF / CRLF — это перенос строк на Windows, можно игнорировать.
git push может писать Everything up-to-date, если ты пушишь не ту ветку, в которой сделал(а) коммит.
